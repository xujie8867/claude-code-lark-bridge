# CTRiskGuard：把两道风控写进 CT 的 EA

`CTRiskGuard.mqh` 把原来由外部 Python 脚本每分钟轮询执行的两道风控，搬到 `ClaudeTrendSingle.mq5` 内部执行。

> ⚠️ **本文件没有编译过，也没有在 MT5 上运行过**（开发环境里没有 MT5，也没有拿到 `ClaudeTrendSingle.mq5` 的源码）。上线前必须按下面的"验证步骤"逐项过一遍。

## 规则

| 规则 | 行为 |
|---|---|
| **单笔浮盈封顶** | 任何一笔 CT 持仓的 `POSITION_PROFIT` ≥ 1,200 美元，立即市价平仓。每个 tick 检查一次，另加每秒一次的定时器兜底。判断字段和原 Python 脚本一致（只看 profit，不含库存费和佣金）。 |
| **合并持仓上限** | 四个 CT magic 的未平仓合计不超过 8 笔。**开仓前**：已满 8 笔就拒绝开新单。**已经超了**（比如重启之后）：从最新开的那笔开始平，平到剩 8 笔为止。 |
| **作用范围** | 只统计、只操作 magic 在 `InpGuardMagics` 里的持仓，默认是 `20261107,20261110,20261111,20261112`。v9.39（86414/86415）和 ClaudeXMBreak 的单不会被碰。 |

设计要点：
- **防止并发超限**：四张图上的 CT 可能同时出信号、同时去抢最后一个名额。开仓前后用一个终端全局变量当锁（`CTGuard_BeginOpen` / `CTGuard_EndOpen`），保证"数持仓、下单"这一段同一时间只有一张图在做。锁超过 10 秒没释放会被自动接管，防止某张图崩溃后把锁占死。
- **四个实例互为备份**：每个 CT 实例都对全部四个 magic 执行两条规则。平仓是按订单号下的，几个实例同时动手也不会多平，后到的那个请求只会失败。
- **平仓失败会重试**：同一笔单每 2 秒最多重试一次，每次都写日志。

## 接入 EA（改 5 处）

```mql5
#include "CTRiskGuard.mqh"              // 1. 文件放在 EA 同目录

int OnInit()
  {
   // ... 原有代码 ...
   if(!CTGuard_Init()) return INIT_FAILED;   // 2. 初始化；启动时如已超限会立即处理
   EventSetTimer(1);                         //    EA 已经有定时器的话，这一行不要重复加
   return INIT_SUCCEEDED;
  }

void OnDeinit(const int reason) { CTGuard_Deinit(); /* 原有代码 */ }

void OnTick()
  {
   CTGuard_Check();                          // 3. 放在 OnTick 的第一行
   // ... 原有代码 ...
  }

void OnTimer() { CTGuard_Check(); /* 原有代码 */ }   // 4. 行情清淡时也能触发

// 5. 每一个开仓的位置，前后各加一行：
if(!CTGuard_BeginOpen()) return;             // 已满 8 笔，或者别的图正在开仓
bool ok = trade.Buy(...);                    // 原有的开仓代码，不改
CTGuard_EndOpen();                           // 不管开仓成功还是失败，都必须调用
```

第 5 处最容易出错：`BeginOpen` 返回 true 之后，**每一条代码路径都必须走到 `EndOpen`**，包括开仓报错后提前 return 的分支。漏掉的话，其他图会被挡住最多 10 秒。

## 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `InpGuardEnable` | true | 总开关 |
| `InpGuardProfitCapUSD` | 1200 | 单笔浮盈封顶，填 0 关闭 |
| `InpGuardMaxPositions` | 8 | 合并持仓上限，填 0 关闭 |
| `InpGuardMagics` | 四个 CT magic | 逗号分隔。**四张图必须填一样的值** |
| `InpGuardDeviationPts` | 50 | 风控平仓允许的最大滑点（点） |

## 验证步骤（全部通过后，外部脚本才能退役）

1. **编译**：MetaEditor 里 0 错误、0 警告。
2. **策略测试器，验证封顶**：把 `InpGuardProfitCapUSD` 临时调到很小（比如 5），回测一周。日志里应该出现 `CTGuard: PROFIT_CAP close ... OK`，对应的单在浮盈刚过 5 美元时被平掉。
3. **策略测试器，验证拒单**：把 `InpGuardMaxPositions` 临时调成 1。日志里应该出现 `open refused`，任何时刻持仓都不超过 1 笔。
4. **回归对比**：两个参数都填 0（关闭），回测结果必须和接入前**逐笔一致**。这一步证明接入没有改动原有的交易逻辑。
5. **另开一个 demo 账户做多图测试**：四张图都挂上，把上限调成 2，确认合计不超过 2 笔；再手动把上限改成 1 并重启 EA，确认最新开的那笔被平掉。
6. **主终端上线**：四张图换成新版本，参数用正式值。外部的浮盈封顶脚本继续并行运行。
7. **退役条件**：EA 版连续运行满 5 个交易日，期间日志无异常；并且至少看到一次 EA 抢在外部脚本之前触发（或者期间没有触发机会，但第 2、3、5 步都通过）。满足后外部脚本退役。

## 已知的限制

- **只统计持仓，不统计挂单。** CT 如果用挂单入场，挂单成交的那一刻可能超过 8 笔，随后会被"平最新"规则处理掉。CT 用市价单入场的话没有这个问题。
- **休市时平不掉。** 某个品种休市期间，它的超限持仓要等开市后才能平，期间日志里会每 2 秒出现一次失败记录。
- **四张图的参数必须一致。** 如果某张图的 magic 列表或上限填得不一样，各实例的判断会互相矛盾。
- **封顶和 2R 止盈的关系。** CT 现在是 0.01 手、2R 止盈，单笔浮盈实际到不了 1,200 美元，这条规则目前只是保险。以后如果加大手数，让 2R 超过了 1,200 美元，封顶会提前截断盈利单、改变策略的期望值，**加手数之前必须先带着封顶重新回测**。
